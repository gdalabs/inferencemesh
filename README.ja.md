# InferenceMesh

**[English](README.md) · 日本語 · [한국어](README.ko.md) · [中文](README.zh.md)**

## AI を、お金をかけずに使うためのルーターです

**9社・28モデルの無料枠**を1つの窓口にまとめます。出荷している28モデルは**全部 $0**。
混んでいたり落ちていたりしたら、黙って次のプロバイダに回します。

```
あなたのアプリ  →  InferenceMesh  →  Groq / Gemini / Workers AI / OpenRouter / …
                        （空いていて・条件に合うものを自動で選ぶ）
```

### なぜお得なのか

- **0円で始まる。** クレジットカードは要りません。**鍵すら要りません** — 登録不要で使える
  プロバイダが入っているので、何も設定しなくても答えが返ってきます（実測済み: 環境変数が
  空のコンテナが実際のチャットに応答します）
- **勝手に課金されません。** 有料モデルには**絶対に切り替えません**。無料枠を使い切ったら
  エラーを返します。操作ミスが請求書に変わることはありません
- **無料枠を使い切りにくい。** 1社の枠が尽きても、残っている別の社に自動で回ります。
  分・日・トークンの残量を数えていて、429 をもらう**前に**避けます
- **鍵を足すほど増える。** 使いたい分だけ後から足せます。設定画面が取り方を1手順ずつ
  図で案内し、貼った鍵はその場で実際に試してから保存します

### 何が嬉しいのか（アプリ側）

アプリは `mesh/free` と書くだけです。実際に答えたのが Groq なのか Gemini なのか
Cloudflare Workers AI なのかを、アプリが知る必要はありません。

```
POST /v1/chat/completions   { "model": "mesh/free", "messages": [...] }
```

OpenAI 互換なので、**いま動いているコードのアドレスを変えるだけ**で済みます
（公式 `openai` パッケージで実測済み）。プロバイダごとの SDK は要りません。

### 🔴 ただし、無料はタダではありません

お金は取られませんが、**あなたが送った文章が提供元のモデルの学習に使われることがあります**。
個人情報・医療情報・他人の情報は送らないでください。詳しくは
[「無料」の本当の代金](#無料の本当の代金)を読んでください。**セットアップ画面は、鍵を尋ねる
前にこれを表示します。**

### そのほか

- **依存ゼロ、プロバイダSDKもゼロ。** 使うのは `fetch` だけ。同じバンドルが Node 20+ /
  Cloudflare Workers / Deno / Bun で動きます
- **鍵はあなたのもの（BYOK）。** 鍵は環境変数から読み、あなたのマシンから出ません。
  鍵が無いプロバイダは読み込み時に外され、`warnings` に名前が出ます。**黙って消えません**
- **機密度はフィルタであって好みではありません。** `confidential` のリクエストは、どれだけ
  高得点でも `internal` までのプロバイダには回りません
- **MIT。** ルーターは公開。何に**繋ぐか**と、その答えをどう使うかはあなたのものです

## 鍵もサインアップも無しで始める

```sh
INFERENCEMESH_TOKENS=$(openssl rand -hex 32) docker compose up
```

これで全部です。**プロバイダの鍵が1つも無くても**メッシュは動きます。鍵不要の無料枠を
公開しているプロバイダがあるからです — 実測済み: 環境変数が空のコンテナが、実際のチャット
リクエストに応答します。

compose は隣にある鍵ファイルを読みます。`inferencemesh setup` で保存した鍵は、どこにも
書かなくてもコンテナに渡ります。**これは両方向に効きます**: コンテナがあなたの鍵を持てる
理由であり、そのファイルを絶対にコミットしてはいけない理由でもあります。

```sh
curl localhost:8910/v1/chat/completions \
  -H "authorization: Bearer $INFERENCEMESH_TOKENS" \
  -H 'content-type: application/json' \
  -d '{"model":"mesh/free","messages":[{"role":"user","content":"hello"}]}'
```

鍵を足せばもっと良くなります。起動時に URL が表示されます:

```
[inferencemesh] add keys here: http://127.0.0.1:8910/setup#<token>
```

フラグメント部分のトークンは、あなたが設定した `INFERENCEMESH_TOKENS` のどれかです。
端末から起動した場合はそのままクリックできる形で出ますが、**出力がログになる場所**
（systemd 配下、`docker compose` 経由）では**トークンは出しません** — プロセスより長生きし、
起動した本人以外にも読める場所に、認証情報を書き残さないためです。

セットアップ画面には、プロバイダごとに「何がもらえるか」「**鍵の取り方の手順**」
「鍵の見た目（`nvapi-…`）」「貼り込み欄」「その場での動作確認」が並びます。確認できた鍵は
即座に有効になります。再起動は要りません。

各手順には**その画面の図**が付きます。図は手順文そのものから描かれます — 「」の中の文言が
押すべきコントロールなので、そこを強調します。すべて「イメージ図」と明記してあります。
絵をスクリーンショットのように見せることは、その絵がいつの情報かについて嘘をつくことに
なるからです（コンソールは改装され、絵だけが古いまま残る）。

実物のスクリーンショットがあればそちらが優先されます。`.inferencemesh/shots` に
`groq-1.png` を置けば、Groq の1ステップ目がそれに差し替わります。画像は**他のAPIと同じ
トークンの後ろ**で配信されます（自分のコンソールのスクショには隅にアカウント名が写るため）。
`<img src>` は Authorization ヘッダを送れないので、fetch して blob として表示します。

**あなたの鍵はあなたのマシンから出ません。** ホスト型のコンポーネントは存在しません。鍵が
行く先は2箇所だけ: あなた自身のボリュームにある `600` のファイルと、その鍵の発行元です。
**保存された鍵を返すエンドポイントはありません** — `/v1/providers` は「鍵があるかどうか」
しか返しません — そして**ログにも出ません**。これは主張ではなくテストで強制しています。

`inferencemesh setup` はターミナルから同じことをします。各プロバイダが何をくれるかを述べ、
鍵の取得ページを示し、**保存する前に実際のリクエストで鍵を検証します**。「保存しました」は
安心の材料になりません — 打ち間違えた鍵も、動く鍵と同じように保存されるからです。

### 「無料」の本当の代金

無料は取引であり、その条件はほとんど明示されません。`setup` は何かを尋ねる前にこれを表示します。

- **あなたのプロンプトは提供元のモデルの学習に使われることがあります。** 個人情報・医療情報・
  他人の情報は送らないでください
- **鍵をブラウザやスマホアプリに配らないでください。** サーバー側に置きます。このゲートウェイが
  そのサーバーです
- **稼働の保証はありません。** 無料枠は予告なく終了します
- **思考をそのまま出すモデルがあります**（「The user asks…」）。あなたのコードのバグでは
  ありません
- **このゲートウェイは有料モデルに勝手に切り替えません。** 無料枠を使い切ったらエラーを返します。
  操作ミスが請求に変わることはありません

## インストール

実行ファイル1つ。Node もパッケージマネージャも不要:

```sh
curl -fsSL https://raw.githubusercontent.com/gdalabs/inferencemesh/main/install.sh | sh
```

あなたのプラットフォーム向けのビルドをダウンロードし、**公開されている `SHA256SUMS` と
照合して、照合できなければインストールを拒否します** — バイナリを差し替えられる相手なら
検証を無効化することもできるので、無効化できる検証は検証ではありません。配置先は
`~/.local/bin`。`INFERENCEMESH_BIN_DIR` で変更でき、`INFERENCEMESH_RELEASE_BASE` は
ミラーやオフラインのコピーを指せます。`INFERENCEMESH_SKIP_CHECKSUM=1` で検証を飛ばせますが、
飛ばす理由が必要です。

ライブラリとして、またはソースから動かす場合:

```sh
npm install inferencemesh
```

Node 20 以上。監査すべき実行時依存はありません — コンテナイメージにはコンパイル済みの
出力だけが入っています。

## ライブラリとして使う

```ts
import { InferenceMesh, registryFrom } from 'inferencemesh';
import registryFile from './providers.default.json' with { type: 'json' };

const mesh = new InferenceMesh({ registry: registryFrom(registryFile) });

const res = await mesh.chat({
  model: 'mesh/free',
  messages: [{ role: 'user', content: '日本語で答えて' }],
  mesh: { language: 'ja', privacy: 'public' },
});

console.log(res.choices[0].message.content);
console.log(res.mesh);
// { served_by: 'gemini/gemini-2.5-flash', profile: 'free',
//   attempts: [{ key: 'groq/llama-3.3-70b-versatile', status: 429, ... }],
//   latency_ms: 812, cost_usd: 0 }
```

`res.mesh.attempts` には、途中で試して失敗したものが全部並びます。**隠しません** —
あるプロバイダが 429 を返して黙って別に移ったなら、そう書いてあります。

## ゲートウェイとして使う

```sh
export GROQ_API_KEY=...            # プロバイダを最低1つ
export INFERENCEMESH_TOKENS=$(node -e "console.log(require('crypto').randomBytes(32).toString('hex'))")
npx inferencemesh serve
```

あとは OpenAI クライアントを向けるだけです — 2026-08-22 に**公式の `openai` パッケージで
実測済み**であって、主張ではありません: `models.list()`、usage 付きの completion、
ストリーミング、そして打ち間違えたプロファイルが**リトライ対象ではなく `BadRequestError`
（400）**として届くこと。

| ルート | 用途 |
|---|---|
| `POST /v1/chat/completions` | OpenAI 互換。ストリーミングあり・なし両方 |
| `GET /v1/models` | mesh プロファイルと、具体的な `provider/model` の一覧 |
| `GET /healthz` | ブレーカーの状態、クォータ、読み込み時の警告 |

サーバーは**認証トークンが無ければ起動を拒否**し、**`0.0.0.0` へのバインドも拒否**します
（上書きしない限り）。このプロセスはあなたが持つ全プロバイダの鍵を握っています。共有ネットワーク上の
開いた LLM 中継は、他人があなたの無料枠で推論する装置です。前段に `tailscale serve` か
リバースプロキシを置いてください。

### Cloudflare Workers で

`handleRequest` は素の Fetch ハンドラなので、Worker はこれで全部です。実体は
[`examples/worker.ts`](examples/worker.ts) で、**ビルド時にコンパイルされます** —
README の中にしか無いスニペットは、誰も一度も動かしたことがないスニペットです。

```ts
import { handleRequest, InferenceMesh, registryFrom } from 'inferencemesh';
import registryFile from './providers.json';

/**
 * バインディング。インデックスシグネチャがあるおかげで env をそのまま
 * レジストリに渡せます（各プロバイダが必要な変数名を自分で名乗るので、
 * ここに1つずつ書き並べる必要がありません）。
 */
interface Env {
  GATEWAY_TOKENS: string;
  [key: string]: string | undefined;
}

export default {
  async fetch(req: Request, env: Env): Promise<Response> {
    const mesh = new InferenceMesh({ registry: registryFrom(registryFile, { env }) });
    return handleRequest(req, { mesh, tokens: new Set(env.GATEWAY_TOKENS.split(',')) });
  },
};
```

クォータを isolate の入れ替わりに耐えさせたいなら、KV か Durable Object で `LedgerStorage` を
実装してください。既定のインメモリ実装は isolate と一緒に消えるので、1日の上限に対して
過少にカウントします。

## モデルの指定方法

| `model` | 意味 |
|---|---|
| `mesh/free` | このプロファイルの中でルーティング |
| `mesh/best` `mesh/cheap` `mesh/fast` `mesh/coding` `mesh/vision` `mesh/private` | 組み込みプロファイル |
| `groq/llama-3.3-70b-versatile` | 候補を1つに固定（pin） |

pin はプロファイルの**価格**の好みを上書きしますが、**機密度・能力・コンテキストの
フィルタは上書きしません** — pin を使って機密のテキストを public 相当のプロバイダに
紛れ込ませることはできません。

リクエスト単位の指定は `mesh` オブジェクトに入れます。プロバイダに届く前に取り除かれます:

```json
{
  "model": "mesh/best",
  "messages": [],
  "mesh": {
    "language": "ja",
    "privacy": "confidential",
    "capabilities": ["vision"],
    "minContext": 100000
  }
}
```

## 候補はどう選ばれるか

**ハードフィルタ**（正しさの問題。落ちた候補は何点だろうと対象外）:
機密度の階層 · 必要な能力 · コンテキスト長 · プロファイルの価格上限。

**重み付きスコア**（好みの問題。プロファイルごとに重みが違う）:
`quality` · `cost` · 観測された `latency` · `language` の適性。

**その後、順に**: ブレーカーが開いている候補を落とし（ただしそれで候補が空になるなら無視します
— たぶん落ちているプロバイダでも、プロバイダが無いよりはましなので）、実行時にクォータを確認し、
残った順位付きのリストがフォールバックの連鎖になります。

`inferencemesh route best --language=ja` は、**ネットワークに一切触れずに**判断の全体を
表示します。落ちた候補については、なぜ落ちたのかも出ます。リクエストに載せられるフィルタは
そのままフラグになっているので、何も繋ぐ前にルーティングの疑問に答えられます:

```sh
inferencemesh route best --language=ja
inferencemesh route free --capabilities=vision,tools   # 好みではなく必須要件
inferencemesh route best --privacy=confidential        # 候補が満たすべき下限
inferencemesh route free --min-context=200000
```

実在しない能力・機密度・数値を渡すと、**名指しで拒否**されます。黙って全部を除外したりは
しません — 打ち間違いは「空のレジストリ」ではなく「打ち間違い」として読めるべきです。

### リトライ**しない**もの

`400` と `422` はリクエスト側の誤りで、どのプロバイダでも同じように失敗します。だから連鎖は
即座に止まります。`401` は**リトライします** — 次のプロバイダはその壊れた鍵を共有していないからです。

### 同時に何本まで

レート制限には2つの形があり、**窓（ウィンドウ）なのは片方だけ**です。`quota` は毎分・毎日の
リクエスト数を数えます。`maxConcurrent` は**いま起きている**数を数えます。同時に1本しか
さばけないプロバイダは、毎分の予算がほとんど手つかずのまま fan-out を 429 で弾きます。
窓だけ数えていてもこれは見えません。

```jsonc
{ "id": "some-provider", "maxConcurrent": 2, "models": [ /* ... */ ] }
```

スコープはモデルではなく**プロバイダ**です。上限は資格情報に属するので、1つの鍵の後ろに
2つのモデルがあれば、その2つはアカウントの枠を分け合います。

`quota` も同じ場所に置けます。理由も同じです。「毎分10リクエスト」と書かれた無料枠は、
ほぼ必ず**鍵**に対する制限であって、モデルごとではありません。3つのモデルにその数字を
書けば30本を許すことになり、返ってくる 429 はただの失敗と見分けがつかないので、
メッシュは黙って次のプロバイダに移り、設定の誤りは最後まで表に出ません。
プロバイダ側に1回書けば、モデル自身の予算より先に予約され、一緒に払い戻されます。

```jsonc
{ "id": "orcarouter", "quota": { "requestsPerMinute": 10, "requestsPerDay": 50 } }
```

アカウントの10本をモデルで割って3本ずつにするのは、`maxConcurrent` が拒んでいるのと
同じ推測です。プロバイダが一度も言っていないモデル単位の上限を発明することになり、
トラフィックが偏った瞬間に実容量を絞ります。

塞がっているプロバイダは**待たずに飛ばします** — 空いている先に回るために連鎖があるのですから。
**すべての**候補が塞がっている時に限り、FIFO で最大
`INFERENCEMESH_CONCURRENCY_WAIT_MS`（既定 30000。`0` で待たずに失敗）だけ待ちます。
これは単一プロバイダの場合の話で、いますぐ 503 を返すよりは一瞬待って答えるほうがましだからです。

`maxConcurrent` を書かなければ無制限です。誰も測っていない上限は、推測で実容量を絞ることに
なります。だから出荷レジストリは**実測した所にしか書いていません**: `llm7` は **1** です。
2026-08-22 に並列度を上げていき、2本目のリクエストが
`429 Too many concurrent requests for this client` を返す点を見つけ、3回再現しました。
あなたも同じ方法か、提供元のドキュメントで見つけてください — そして**日付を横に書いてください**。

## 設定

設定はすべて環境変数です。サーバーは独自の設定ファイルを読みません。

| 変数 | 既定 | 意味 |
| --- | --- | --- |
| `INFERENCEMESH_TOKENS` | *(なし)* | カンマ区切りの Bearer トークン。**1つも無ければサーバーは起動を拒否します** — 無認証の LLM 中継は、他人にあなたの無料枠で推論させる装置です |
| `INFERENCEMESH_PORT` | `8910` | 待ち受けポート |
| `INFERENCEMESH_HOST` | `127.0.0.1` | バインド先。`0.0.0.0` にするには `INFERENCEMESH_ALLOW_ANY_HOST=1` も必要です。このプロセスはあなたの全プロバイダ鍵を握っているので |
| `INFERENCEMESH_ALLOW_ANY_HOST` | 未設定 | ループバック以外へのバインドを許可。コンテナ内（ネットワーク名前空間が境界）では設定します。それ以外の場所では一度考えてください |
| `INFERENCEMESH_ALLOWED_ORIGINS` | *(なし)* | ブラウザから直接叩けるオリジン（カンマ区切り）。空なら CORS ヘッダを一切出しません |
| `INFERENCEMESH_PUBLIC_HEALTH` | 未設定 | `1` で `/healthz` をトークン無しで公開。プロバイダID・ブレーカー状態・クォータが出ます。死活監視には便利ですが、配って構わない情報でもありません |
| `INFERENCEMESH_REGISTRY` | *(自動探索)* | レジストリファイルのパス。**存在しないパスを指定した場合はエラー**です。組み込みレジストリへ黙って落ちたりはしません |
| `INFERENCEMESH_KEYS` | `.inferencemesh/keys.env` | セットアップ画面から追加した鍵の保存先。パーミッション 600 |
| `INFERENCEMESH_SHOTS` | `.inferencemesh/shots` | セットアップ手順のスクリーンショット置き場。`<provider>-<n>.png`。無くても構いません（図が描かれます） |
| `INFERENCEMESH_LEDGER` | `.inferencemesh/ledger.json` | クォータのカウンタ。**ボリュームに置いてください**。さもないと再起動のたびにその日の消費を忘れます |
| `INFERENCEMESH_CONCURRENCY_WAIT_MS` | `30000` | *すべての*候補が塞がっている時に待つ時間。`0` で待たずに失敗 |
| `INFERENCEMESH_LANG` | *(ロケール)* | セットアップウィザードの言語（`ja` / `en`）。既定はシステムのロケール |

プロバイダの鍵は各エントリの `apiKeyEnv` が名乗る変数です（`GROQ_API_KEY`、
`OPENROUTER_API_KEY` など）。鍵が無いプロバイダは飛ばされ、`/healthz` に名前が出ます。

## レジストリを生成する

手書きのレジストリは、週単位で動く市場のスナップショットです。手書きの価格は、過ぎた日に
ついての主張です。`sync` はプロバイダ自身のカタログを読んで、機械が知り得る部分だけを書きます。

```sh
inferencemesh sync --provider=redpill    --out=providers.local.json --dry-run
inferencemesh sync --provider=openrouter --out=providers.local.json --dry-run
inferencemesh sync --provider=nous       --out=providers.local.json --dry-run
```

OpenRouter と Nous Portal のカタログは**鍵不要**です。誰のクレジットも使わずに更新できる
2つの経路です。どちらも無料枠だけを読みます（OpenRouter は 2026-08-22 時点で 421 モデル中
22 が価格ゼロ。Nous は 2026-08-28 時点で 371 モデル中 5 が全ての階層でゼロ）。

「無料」とは**公開されている価格が全てゼロ**という意味で、トークン単価だけではありません。
pricing には `web_search` や `image`、キャッシュ系のキー、そして本当に人を引っかけるのは
`overrides` — 時間帯ごとの価格の窓 — も入っています。トークン単価がゼロでも 06:00〜24:00 UTC は
課金する、というモデルは無料ではなく、**無料に見えるだけ**です。これは仮定の話ではなくなりました。
2026-08-28 に `tencent/hy3:free` が、top-level はゼロのまま2つの窓で1日を覆う形で現れています。

### 匿名プレビューはレジストリに入れるものではない

OpenRouter の `stealth/` 名前空間は、**誰のものか言わずに未発表モデルを出す**仕組みです。
2025年4月以降14件 — GPT-4.1、GPT-5、Grok 4 Fast、Xiaomi の MiMo、Meituan の LongCat が
ここを通りました — 中央値で4〜12日走った後、**ID が消えて製品名で再登場します**。無料で、
それでも確実に腐る。だから `sync` は `providers.default.json` に**書き込むこと自体を拒否**し、
毎回の警告で名指しし、`maxPrivacy: "public"` で生成します（運用者が匿名で、プロンプトを
保持するため）。

日付の欄はここでは役に立ちません。2026-08-25 時点で `stealth/ox-alpha` は
`expiration_date: 2098-12-31` — **「終了予定なし」を意味する番兵** — を持っていました。
形式そのものが2週間で終わる出品なのに、です。**唯一の機械可読な警告が、いちばん確実に消える
エントリについて「終わらない」と言っていました。** 日付を信用せず専用のフラグを持つ理由です。

`sync` が新しく作るプロバイダ枠は `maxPrivacy: "public"`（最下位）で出てきて、その旨を表示します。
`internal` を生成するのは、そのプロバイダに何を預けてよいかを sync が決めることになります —
既存エントリに対しては絶対にしない判断を、新規に対しては黙ってやることになるので。

書かないもの: `quality` と `languages`。カタログはモデルの良し悪しも、日本語で会話できるかも
知りません。もっともらしい推測をそこに書けば、`best` プロファイルの順序が静かに入れ替わり、
非英語の利用者すべてに悪い結果を返します — 検証していない価格と同じ失敗で、しかも請求書という
気づく手段がありません。新しいエントリは**未評価**のまま出てきて、評価するまでは中立に
スコアされます。

同じく書かないもの: 既存エントリの `maxPrivacy`。カタログと突き合わせても「人間が上げた」のか
「提供元が下げた」のかを区別できず、その2つは正反対の対応を要します。カタログが支持する階層は
`evidencePrivacy` に別で記録され、**カタログ自身の前回の答えと**比較されます。ファイルが
カタログより広い階層を許している場合、`sync` は非ゼロで終了します — 階層を下げるか、
`privacyVerifiedAt` を記録するまで。そして**カタログ側の答えが変わった瞬間に再び鳴ります**。
古い承認が意味を失うのはまさにその時だからです。

カタログから消えたモデルは、**削除ではなく無効化**されます。削除するとあなたの評価が失われ、
次の差分で「消えたこと」自体が見えなくなります。

### 唯一、事前に届く警告

腐敗はふつう事後に分かります — 応答を待っている利用者によって。`expiration_date` だけが例外で、
提供元が「この無料枠はこの日に終わる」と機械可読な形で宣言したものです。`sync` はこれを
`expiresAt` として記録し、60日以内なら警告します。これを書いた時点で、nvidia の `:free` の
うち3つが2日後に切れる予定でした。

`probe` と `route` も同じことを表示します。sync のレポートは「レジストリを作り直している時」に
しか読まれず、それは「月曜に消えるモデルにルーティングしている」と知りたい瞬間ではないからです。

ルーティングには一切使いません。日付は意思の表明であって観測ではなく、宣言した期限を超えて
生き延びたモデルは、JSONファイルの中の計算で落とされるのではなく動き続けるべきです。

### カタログに分からないこと

**「書いていない」は「否定」ではありません。** RedPill には能力を一切宣言していないモデルが
14件あり、うち6件は TEE 上で、少なくともその1つはツール呼び出しを問題なくこなします。sync は
そういうモデルには `text` だけを記録して警告します。**誰も主張していない「ツール非対応」を
書いたりはしませんし**、あなたが実測して書いた能力を上書きすることもありません。

この最後の点は聞こえよりも狭い話で、正確に言う価値があります: カタログが所有するのは
**実際に表現できる能力だけ** — `text` `vision` `tools` `json` — であって、それ以外ではありません。
**`code` を記述できるカタログは存在しません。** 能力リストを丸ごと上書きすれば、何も変わって
いないモデルから手書きの `code` が消え、`mesh/coding` がそのモデルを見失います。カタログは
観測した分を更新するだけで、見えないものを消す権限はありません。

`is_tee: true` は `internal` にはなりますが、`confidential` にはなりません。それは提供元が
JSON のフィールドで自分について主張しているだけで、誰もアテステーションを検証していません。
しかも RedPill では TEE の運用者が想定した会社とは限りません — `providers` の一覧には
`chutes` `near-ai` `tinfoil` `secretai` も並び、複数挙がっているモデルでは呼び出し側に
選ぶ手段がありません。

## レジストリを正直に保つ

`providers.default.json` が出荷するのは**無料枠だけ、価格ゼロだけ**です — プロバイダについての
数値のうち、**嘘になる形で古くなり得ない唯一の数**だからです。有料モデルは意図的に出荷しません。
価格は予告なく変わり、古い価格は大声で失敗せず、`cheap` プロファイルの順序を静かに入れ替えます。
`providers.example.json` をコピーして、**自分で検証した価格**を書いてください。

モデルIDと無料枠は**静かに腐ります**。最初の症状は、応答を待っている利用者です。それを
終了コードに変えましょう:

```sh
inferencemesh version          # どのビルドか
inferencemesh probe            # 全候補を1回ずつ呼ぶ
inferencemesh probe --json     # スケジューラ向け。`ending` も入っています
```

`probe` は、似て非なる2つの発見を分けます: `404`/`400` は「IDが消えた」で人間の対応が要ります
（`BROKE`、終了コード 1）。`429` は「無料枠が設計通りに動いている」です（`limit`、終了コード 0）。
後者で毎晩鳴らすのは、監視を無視する習慣を人に教える方法です。

`quality` と `languages` は手で維持している**相対的な見積もり**であって、ベンチマークの結果では
ありません。**あなたの**レジストリの順序が正しければ十分です。ただし `languages` のほうは、
少なくとも**証拠で否定できます**:

```sh
inferencemesh probe --language=ja          # 日本語で質問し、返答を採点する
inferencemesh probe --language=ja --json
```

判定できるのは、文字種だけで言語が決まるもの — 日本語（かなを見るので、中国語が日本語として
通ることはありません）、中国語、韓国語、ロシア語、アラビア語、ヒンディー語、タイ語、ヘブライ語、
ギリシャ語、アルメニア語、ジョージア語、ベンガル語、タミル語 — に加えて、機能語で区別できる
ラテン文字圏の11言語です。それ以外は失敗ではなく `unjudged`（判定不能）と報告します。

文字種を共有する言語については、**区別する文字**も見ます: ウクライナ語の返答はロシア語の主張を
裏付けませんし、ペルシア語はアラビア語として通りません。`zh-Hant` に簡体字で答えることも
できません — 一方 `zh` 単体はどちらも受け入れます。どちらも要求していないからです。この検査は
**否定にしか使えません**。区別する材料が無い返答は文字種の判定のままにし、両方の固有文字が
同時に出た返答は「発見」ではなく「証拠なし」として扱います。区別する文字が存在しない組
（ヒンディー語とマラーティー語）は、いまも区別できません。

各候補には**その言語で書かれた**質問を2つ投げます — 英語で「日本語で答えて」と指示するのは、
言語ではなく指示追従を測ることになるので — 返答を文字種と機能語で採点します。結果はレジストリの
主張と並べて表示され、**FAULT になるのは1方向だけ**です: レジストリが「対応している」と
言っているのに、モデルがその言語で答えない場合（終了コード 1）。低く評価されているのに問題なく
答えるモデルは `understated` として報告されます。読む価値はありますが、誰かを起こす話ではありません。

全候補が到達不能かレート制限だった実行は、`no contradictions`（矛盾なし）ではなく
**`nothing was measured`（何も測っていない）**と報告します。`--json` は `ok` の隣に `judged`
の件数を持ちます。**測定ゼロでの `ok: true` は、いちばん誤解を招く緑**だからです。

**スコアは絶対に書き込みません。** 日本語で答えたことは compliance（要求に従ったか）であって
competence（どれだけ上手いか）ではなく、合格を `0.84` に変えることは、**測定値が入るべき場所に
捏造した数値を置く**ことです — 検証していない価格と同じ失敗です。判定できないものは判定できないと
言います: 判定器の無い言語、隣接言語と区別するには短すぎる返答、トークン上限で思考の途中で
切れた返答 — いずれも失敗ではなく `unjudged` として返ります。最後のものは仮定の話ではありません。
このコマンドの最初の実行は、**あるモデルが英語で「日本語で答えよう」と考えている最中に、
日本語の失敗だと判定しました**。

## 新しいプロバイダを見つける

新規参入は意図的に推論を配ります — 慈善ではなく顧客獲得です — なので、今日いちばん良い無料枠は、
あなたのレジストリを書いた時点では存在しなかったものであることが多い。手書きの一覧は、出荷した
その月に古くなります。

```sh
node scripts/discover-providers.mjs        # 新しいものがあれば終了コード 10
node scripts/discover-providers.mjs --json
```

各プロバイダ自身の `/v1/models` を前回の実行と比較し（追加だけでなく、**あなたのレジストリを
壊す側である削除**も捕まえます）、Hacker News とスター付きのコミュニティ一覧も走査します。
情報源はすべて鍵不要です。鍵の要る情報源は、**あなたが見なくなったのとちょうど同じ時に**
動かなくなるからです。見つかったものは候補です。追加する前に `probe` で確認してください。

## 鍵がまったく要らないプロバイダ

プロバイダは `apiKeyOptional: true` を宣言できます。その場合、資格情報が無くても読み込まれ、
アダプタは `Authorization` ヘッダを**送りません** — 空の `Bearer ` を不正として拒否する
ゲートウェイがあり、それは壊れた鍵と見分けがつかないからです。

これによりサインアップゼロのデプロイが可能になります。環境変数が空でも、公開枠のプロバイダだけで
メッシュはルーティングします。出荷レジストリではそうしたプロバイダを `maxPrivacy: "public"` に
固定してあり、**そのままにしておくべきです** — 誰でも匿名で叩けるエンドポイントは、
ログに残って困るものを送る場所ではありません。

## 開発

```sh
npm test        # ビルドしてからスイートを実行（ネットワーク不要・鍵不要）
npm run build
```

スイートの失敗経路は、**わざと壊した入力**で1つずつ動かしてあります — 壊れたレジストリ、
空のトークン集合、JSON の途中で切れたストリームチャンク、期限切れのクォータ窓 —
**一度も発火したことのない検査は、動くと分かっていない検査**だからです。
